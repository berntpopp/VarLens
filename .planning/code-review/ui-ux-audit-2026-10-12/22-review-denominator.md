# 22 · Review: `feat/carrier-frequency-denominator` (#555, audit 09 Part 2)

**What this change does:** Case and cohort views now show one carrier frequency: summary `carrier_count` ÷ ready cases of the same build holding ≥1 call of the same class (small/SV/CNV/STR), on both backends, via `src/shared/sql/carrier-frequency.ts`. Every summary/gene-burden contribution keeps only "carrier rows" (`carrierRowSql`), and the UI is relabelled. The per-build × class maths, the ready-case filter, mixed builds, SV-only cases, a case with zero calls of a class (no row in `bt`, so NULL and no divide-by-zero) and the sort shortcut are all right. The parity tests (`carrier-frequency.test.ts`, backend-parity "#555") really test the new semantics.

**Must fix**
1. **JSON variants with `GTNum-Index` 0 drop out of the cohort** (`shared/utils/genotype.ts` `NON_CARRIER_GENOTYPES`). The JSON importer stores the raw number as text (`FieldMapper.ts:95`). The fixtures hold 0/1/2 (demo-case: 0 on APOE/LMNA/TSC2 AD rows, 2 on X-linked DMD/AR). The meaning is not documented anywhere (`docs/reference/supported-formats.md:54`). VCF never stores reference genotypes: `VcfMapper.ts:70-97` keeps only carried ALTs plus SV no-calls. So the reference entries (`'0'`, `0/0`, `0/.`…) in the list only ever match JSON `'0'` rows, and those are reported variants that used to count as carriers. **Fix:** cut the list down to the no-calls `'.'`, `'./.'`, `'.|.'`. That is about 2 lines.
2. **Existing databases keep the old counts, and deleting a case now leaves phantom rows.** There is no migration. Summaries built before this branch still count SV/CNV/STR no-calls. The new remove paths subtract only carrier rows, so `carrier_count` never reaches 0 and the row never goes away. **Fix:** a SQLite migration and a PG migration that mark the summary stale, as v43/0027 did (`migrations.ts:1918-1929`). That is about 15 lines.
3. **JSON zygosity is now labelled wrongly** (`CohortDataTable.vue`, `ZYGOSITY_REMAINDER_LABEL='hemi'`). `'1'` is in `HEMI_GENOTYPES` and `'2'` is in no class. So every JSON carrier shows up as "+N hemi", with Het/Hom at 0. The classification already existed on main, but main called the remainder "other", which was honest. **Fix now:** keep "other" (or "hemi/other") in the label and the help text. **Root fix later:** map GTNum to VCF text at import, once someone confirms what the codes mean.

**Should fix**
4. **The case view hides a stale summary.** Its numerator now comes from `cohort_variant_summary`, but the denominator is computed live. A summary that is stale or failed shows old or NULL carriers next to a fresh denominator, so the number is too low. The filters also let NULL rows through. Only the cohort view and the overview use `useSummaryFreshness`. **Fix:** reuse `watchSummaryFreshness` in the case view and show a "refreshing" state on the column. The two views can also disagree while the cohort query has `_count_needed`/keyset caching and the case view does not. That is cosmetic.
5. **The denominator runs on every query, at the expected web scale** (10k exomes, about 1e9 `variants_all` rows). Each query does 4 scans over `cases` with 4 × 10k probes on `idx_variants_case_type`: about 40–200 ms warm on PG and seconds cold. It also runs in the count query and on every case-view page. SQLite is cheaper (about 40k btree seeks, roughly 50–100 ms) and rarely sees 10k cases. **Leanest fix:** memoise the `bt` rows by `summaryVersion()`, which already includes the case count (`PostgresCohortRepository.ts:144`), and inline them as `VALUES`. Do the same on SQLite with the column-meta cache key. No table is needed.
6. **`variant_frequency` is written but never read.** No reader is left in `src/`. Every publish and delete still does a GROUP BY plus upsert over all rows of the case, on both backends (`VariantFrequencyService.ts`, `postgres-import-publication.ts`, `PostgresCaseLifecycleRepository.ts:358`, `delete-operations.ts`, `import-recovery.ts`). **Fix:** a follow-up PR deletes the service and its calls and drops the table. That saves about 200 lines and one full per-case pass per import.
7. **There are no tests for 1–3:** JSON numeric GTs through add/remove, and an old-summary stale flag.

**Nice to have**
8. **The custom % field rewrites what you type** (`CarrierFrequencyField.vue`, `watch(model)`). Typing `7` gives 0.07, which is written back as `"7.000000000000001"`. **Fix:** skip the write-back when `parseFloat(customPercent)/100 === val`.
9. **Each row evaluates the frequency subquery up to 3 times** (`core-filters.ts` `IS NULL OR <=` plus the projection). SQLite does not reuse the result. **Fix:** `COALESCE(expr, 0) <= max` keeps rows without a frequency and evaluates it once.

UI is config-driven: copy lives in `uiCopyConfig.ts`/`columnHelp.ts` and the classes in `domain.config.ts`. The labels say "patients in this database" and "not for BA1, BS1 or PM2". The `12 / 340` hint in the cell is not built.

Verdict: fix 1, 2 and 3 first. Lean: about -200 lines possible (6).
Not checked: the test suite was not run (read-only, and the native ABI would need a rebuild). The PG planner choice for the EXISTS probes was not checked with EXPLAIN on a 10k-case dataset.
