# Milestone v0.3.0: Cohort Analysis, Security & Import Enhancements

**Status:** SHIPPED 2026-01-28
**Phases:** 13-18
**Total Plans:** 13

## Overview

This milestone transforms Varlens from a single-sample viewer into a cohort analysis platform. The work delivers SQLCipher database encryption, database selection/switching, batch import with password-protected ZIP support, external links to genomic databases, OMIM disease associations, and cross-case cohort analysis with variant aggregation. Phases are ordered by dependency chain: the native module swap is highest risk and foundational, database lifecycle enables multi-file workflows, import infrastructure enables cohort analysis, and external links / OMIM are independent enhancements that slot in between.

## Phases

### Phase 13: SQLCipher Foundation

**Goal**: App uses the encrypted database library with all existing functionality preserved across all three platforms -- no user-facing changes yet, but the encryption infrastructure is in place.
**Depends on**: None (foundation for all subsequent phases)
**Plans**: 2 plans

Plans:
- [x] 13-01: Native module swap from better-sqlite3 to better-sqlite3-multiple-ciphers with full build pipeline update
- [x] 13-02: PRAGMA key integration into DatabaseService constructor with FTS5 ordering, encrypted database tests

**Details:**
- Swapped npm dependency from better-sqlite3 to better-sqlite3-multiple-ciphers v12.6.2
- Updated all build scripts, electron-vite externalization, source imports, and test imports
- DatabaseService constructor accepts optional encryptionKey parameter
- PRAGMA key issued as first operation (before WAL, foreign keys, schema init)
- 8 comprehensive encryption proof tests covering full lifecycle
- All 114 existing tests pass unchanged

**Requirements:** DBSC-01, DBSC-02, DBSC-03, DBSC-07, DBSC-08

Plans:

- [x] 15-02: Clickable data values in variant table columns as external links with visual indicators and error feedback
- [x] 15-03: Configurable external links with Pinia store, settings dialog, URL template system, and dynamic domain allowlist sync

**Details:**

- Clickable data values in variant table (position, chr, ClinVar, gene symbol)

### Phase 16: Batch Import & ZIP Extraction

**Goal**: User can import multiple case files at once -- from multi-file selection, folder selection, or a password-protected ZIP archive -- with per-file progress and error isolation.
**Depends on**: Phase 14 (database lifecycle must support stable connections for sequential imports)
**Plans**: 2 plans

Plans:
- [x] 16-01: BatchImportOrchestrator with multi-file picker, folder selection, sequential processing, aggregate progress, and summary report
- [x] 16-02: ZipExtractor with password prompt, temp directory extraction, Zip Slip prevention, and pipeline integration

**Details:**
- BatchImportService with sequential processing and per-file error isolation
- Upfront duplicate check with Skip/Overwrite radio group
- 4 batch import IPC channels + 4 ZIP IPC channels
- BatchImportDialog with 4 phases (idle, duplicate-review, importing, summary)
- ZipExtractor with Zip Slip path traversal prevention
- TempDirectoryManager for cleanup lifecycle
- adm-zip (pure JS) for cross-platform ZIP support

**Requirements:** BTCH-01, BTCH-02, BTCH-03, BTCH-04, BTCH-05, BTCH-06, ZIMP-01, ZIMP-02, ZIMP-03, ZIMP-04, ZIMP-05

**Goal**: User sees OMIM MIM numbers inline in the variant table and can link directly to OMIM entries using extracted MIM numbers.

Plans:

**Details:**

**Requirements:** OMIM-01, OMIM-02 (partial), OMIM-03 (partial), OMIM-04 (partial), OMIM-05

### Phase 18: Cohort Analysis

**Goal**: User can analyze variants across all imported cases in a dedicated cohort view with aggregated statistics, carrier counts, and gene-level burden summaries.
**Depends on**: Phase 16 (batch import), Phase 17 (OMIM data enriches cohort display)
**Plans**: 2 plans

Plans:
- [x] 18-01: Cohort SQL views, IPC handlers, composite indexes, and CohortView with aggregated variant table
- [x] 18-02: Cohort search, carrier summary, gene-level burden aggregation, and per-case drill-down

**Details:**
- CohortService with GROUP BY aggregation, carrier query, gene burden
- Composite index on (chr, pos, ref, alt) for performance
- LIMIT/OFFSET pagination for cohort (not cursor-based due to GROUP BY)
- Tab-based navigation (Case Analysis / Cohort Analysis)
- Hybrid search: FTS5 for genes, chr:pos for positions, LIKE for HGVS
- Expandable rows with lazy-loaded carrier details
- CohortDashboard with collapsible summary stats
- GeneBurdenTable with per-gene variant counts
- Navigate-to-case drill-down from cohort to individual cases
- 300ms debounced search

**Requirements:** CHRT-01, CHRT-02, CHRT-03, CHRT-04, CHRT-05, CHRT-06, CHRT-07, CHRT-08, CHRT-09, CHRT-10

## Milestone Summary

**Key Decisions:**

| # | Decision | Rationale | Phase |
|---|----------|-----------|-------|
| 1 | Use better-sqlite3-multiple-ciphers v12.6.2 | Matches existing better-sqlite3 version for compatibility | 13 |
| 2 | Keep @types/better-sqlite3 devDependency | TypeScript types are compatible with both libraries | 13 |
| 3 | PRAGMA key ordering: key, WAL, foreign keys, schema | Encryption key must be first operation after opening | 13 |
| 4 | Simple JSON file for recent databases | Avoid electron-store (ESM-only) | 14 |
| 5 | Rollback pattern in switchDatabase | User should never lose database connection on failed switch | 14 |
| 6 | Encryption detection via test SELECT query | SQLCipher doesn't mark file headers | 14 |
| 7 | Backward-compatible getDatabaseService wrapper | All existing IPC handlers continue unchanged | 14 |
| 8 | VTooltip default contentClass bg-secondary | Light gray tooltips unreadable on light backgrounds | 14 |
| 9 | Pure URL builders with primitive parameters | Testability and reuse | 15 |
| 10 | null return semantics for missing data | UI layer interprets as no link | 15 |
| 11 | URL template system for external links | User-configurable links with variable substitution | 15 |
| 12 | Store genome build in externalLinksStore | Affects multiple links, user-configurable | 15 |
| 13 | Dynamic domain allowlist sync | Security: domains synced from renderer to main | 15 |
| 14 | adm-zip (pure JS) for ZIP extraction | No native rebuild needed, cross-platform | 16 |
| 15 | getData(password) over extractAllTo for ZIP | extractAllTo triggers uncaught zlib errors | 16 |
| 16 | Check both encrypted/encripted header properties | @types/adm-zip typo compatibility | 16 |
| 17 | OMIM extraction uses selected transcript pattern | MIM numbers are plain strings, same pattern as gene_symbol | 17 |
| 18 | FTS5 rebuild strategy for schema upgrades | DROP and recreate on schema changes | 17 |
| 19 | OMIM link uses dedicated inline pattern | Simpler UX with direct buildOmimUrl | 17 |
| 20 | LIMIT/OFFSET pagination for cohort | GROUP BY makes cursor pagination complex | 18 |
| 21 | Composite index on (chr, pos, ref, alt) | Essential for GROUP BY performance | 18 |
| 22 | Separate tab for cohort analysis | Different workflow from single-case | 18 |
| 23 | FTS5 for gene search with escaping | Special characters treated as literals | 18 |
| 24 | Lazy loading of carrier data | Minimize queries, cache in Map | 18 |
| 25 | 300ms search debounce | Prevent flooding backend with queries | 18 |
