## Goal

Reshape the PostgreSQL storage layer so a 1000-WGS-case corpus stops being a single un-VACUUMable heap and the gene-burden surface stops doing a live `GROUP BY` over `variants` on every load:

1. **Partition the variant heap by chromosome** (`variants`, its FK children, and `cohort_variant_summary`) so VACUUM/ANALYZE/index builds are partition-local and chr-scoped queries prune.
2. **Convert `info_json TEXT → JSONB`** inside the *same* partition rewrite (one heap rewrite, not two) so future INFO-field queries are not full-table scans, and ship the **STORED-generated-column mechanism** for promoting hot INFO fields to btree-indexable columns.
3. **Make the coordinate BRIN index partition-local** so range/gene-region scans stay cheap as the corpus grows.
4. **Materialise PG `gene_burden_summary`** mirroring Sprint A's `cohort_variant_summary` pattern, and put the gene-burden surface behind **server-side pagination** with a **"min affected cases" pre-filter** — with mandatory **cohort-view parity**.

This is **PostgreSQL-physical-shape work**. SQLite is unchanged structurally (it does not partition, `info_json` stays `TEXT`, and `gene_burden_summary` already exists at `v31`); the contract is that **query results stay backend-equal** (output parity, per Sprint A's gate-9 precedent), not that the storage rows match.

The sprint exits when the **8-case annotated WGS query perf harness** (built in PR-0) shows all five budgets passing with ≥25 % margin on the partitioned + JSONB + BRIN schema, a new artifact lands under `.planning/artifacts/perf/postgres-query/`, and both `make ci-full` and `VARLENS_WEB=1 make ci` are green.

## Reality-check corrections (verified against `main @ ed203e4e`)

The audit was a static read at `f23709db` (pre-Sprint-A). These items diverge from the audit text and **drive the spec** — do not re-derive them from the audit:

- **RC-1 — F1 FK blast radius.** `variants.id BIGSERIAL PRIMARY KEY` (single column, `0003_create_variants.sql:5`) is referenced by **six** `ON DELETE CASCADE` FKs: `variant_transcripts.variant_id`, `variant_sv.variant_id`, `variant_cnv.variant_id`, `variant_str.variant_id` (all `0003`), **`case_variant_annotations.variant_id` and `variant_tags.variant_id` (`0005_create_workflow_tables.sql:19,39` — the audit did not name these two)**. PostgreSQL requires the partition key (`chr`) to be part of every PK/unique constraint on a partitioned table, so `variants` PK must become `(id, chr)`, and **all six** child FKs must reference `(id, chr)` — none of the six children carry a `chr` column today. Partitioning `variants` therefore cascades a `chr`-denormalisation + composite-FK change onto six tables, not four.
- **RC-2 — migration runner is one big transaction with a 30 s statement timeout.** `PostgresMigrationRunner.migrate()` runs `BEGIN`, applies **all** pending migrations, then `COMMIT` (`PostgresMigrationRunner.ts:29-68`); the whole file is one `client.query(sql)` (no statement splitting, `:56`). Session `statement_timeout=30000`, `lock_timeout=5000`, `idle_in_transaction_session_timeout=10000` (`config.ts:26-31`). Consequences for PR-1: a data-rewriting migration **must** open with `SET LOCAL statement_timeout = 0; SET LOCAL lock_timeout = '0'; SET LOCAL idle_in_transaction_session_timeout = 0;` and **cannot** use `CREATE INDEX CONCURRENTLY` (forbidden in a txn). Data-migrating-migration precedent exists (`0010`/`0011` run `INSERT … SELECT … ON CONFLICT`).
- **RC-3 — `cohort_variant_summary` is already chr-partition-ready.** Its PK is `(chr, pos, ref, alt, variant_type, genome_build)` with `chr` leading (`0010_cohort_summary.sql`), so `PARTITION BY LIST (chr)` needs no PK change. Its six secondary indexes (`idx_cvs_*`) carry no `chr` — they become partition-local indexes on the partitioned parent (auto-propagated, PG 11+).
- **RC-4 — BRIN and gene-trigram indexes already exist.** Sprint A's `0007_perf_indexes.sql:14` shipped `variants_brin_chr_pos USING BRIN (chr, pos)` and `:18` `variants_gene_trgm USING GIN (gene_symbol gin_trgm_ops)`. F3 is therefore **"recreate BRIN as partition-local + tune `pages_per_range`"**, not "add BRIN." The audit's "no BRIN" evidence predates Sprint A.
- **RC-5 — F2's GIN index is speculative; there are no current "hot INFO fields" left to promote.** `info_json` has **zero** runtime read sites (no `JSON.parse`, no `->>`, no `WHERE` predicate; only passed opaquely to the renderer and a COPY round-trip test). `info-field-registry.ts` already promotes the only queried INFO-derived fields (`gnomad_af`, `cadd`, `clinvar`) to dedicated columns. So: the **TEXT→JSONB type change** is the expensive-to-defer part worth doing inside the rewrite; the **GIN(jsonb_path_ops) index** and any **generated columns** are evidence-gated (the audit's own "What Was NOT Confirmed" says "if users almost never query custom INFO fields, F2's GIN index is overkill").
- **RC-6 — the exit criterion is unachievable with today's fixture.** The WGS harness imports the GIAB HG002 fixture as **one** case (no multi-case loop; `postgres-vcf-wgs-import.perf.test.ts`). 3 of the 5 budgeted queries (`gene query`, `impact/pathogenicity filter`, `text search`) report `budgetStatus: 'unavailable'` because the fixture is **unannotated** → `rows === 0` → not representative (`postgres-wgs-query.perf.test.ts:118-127`; budgets doc evidence run, 2026-04-30). "All five pass with 25 % margin" is only meaningful on an **annotated, multi-case** fixture — which PR-0 must build.
- **RC-7 — `GeneBurdenTable.vue` is dead code.** It is imported nowhere in `src/`. The live cohort "Gene Burden" tab renders `association/GeneBurdenView.vue` (statistical association analysis via `cohort:geneBurdenCompare`), which never calls `getGeneBurden()`. F8's renderer half (PR-3) must **wire a gene-burden *summary* surface into the app**, not merely swap a table type on an in-use component.
- **RC-8 — `getGeneBurden` is parameter-less on both backends and in the web route.** Contract `getGeneBurden: () => Promise<IpcResult<GeneBurden[]>>` (`src/shared/ipc/domains/cohort.ts:28`), returns the **entire** array; SQLite reads `gene_burden_summary` (`cohort.ts:440`), PG does a **live `GROUP BY` over `variants`** (`PostgresCohortRepository.ts:486`, no `gene_burden_summary`, no `genome_build` grouping — a parity divergence from SQLite, which groups by `genome_build`). The web route delegates to the same `PostgresReadExecutor` (`src/web/server/routes/cohort.ts:84`).
- **RC-9 — `gene_burden_summary` is NOT incrementally maintained in SQLite.** `incrementalAdd`/`incrementalRemove` only mark it stale (`CohortSummaryService.ts:75,99` — comment `// gene_burden_summary not updated`); it is only ever fully rebuilt by `REBUILD_GENE_BURDEN_SQL` (`src/shared/sql/cohort-summary-rebuild.ts:101`). PG must mirror this (rebuild-only), **not** invent incremental gene-burden maintenance.
- **RC-10 — Docker init scripts are an out-of-sync parallel DDL path.** `scripts/postgres/init-db/*.sql` (used only on a fresh Docker volume) still use trigger-based `search_document` and predate `0004`. Tests create schemas via the migration runner, not the init scripts, so the migration path is what's gated — but PR-1's rewrite migration must be verified to run on a schema bootstrapped *either* way.

## Project-rule constraints (all PRs)

- **Branch discipline.** No feature commits on `main` (`AGENTS.md`). Each PR on its own branch; worktrees if running in parallel — though PR-1→2→3 are sequenced.
- **Migrations are agent-health-exempt, baseline must not grow unsilently.** `check-agent-health.mjs` ignores any path with a `migrations`/`migration` segment and any `migrations.ts` (`:152-165`); migration SQL is exempt. The PG-baseline gate (`agent-health-postgres-baseline.json`, monotonic-decrease) and the `runNamed … :vN` suffix gate still apply to any new repository code (PR-1/PR-2). New non-migration files target 150–400 lines, ≤600 with PR justification.
- **No `console.*`.** New code uses `mainLogger` (main) / `logService` (renderer); worker bootstrap exceptions per `AGENTS.md`.
- **IPC domain-module + preload-contract.** PR-3's new method follows the full 8-step checklist; `preload-contract.test.ts` stays green.
- **Never lower thresholds** (`feedback_never_lower_thresholds.md`). Coverage/lint/typecheck stay; failing suites are fixed, not weakened.
- **Cohort parity** (`feedback_cohort_parity.md`). PR-3 ships case + cohort gene-burden parity in the same PR.
- **`.planning/` for all specs/plans/artifacts** (never `docs/`). Perf artifacts under `.planning/artifacts/perf/postgres-query/` are gitignored; numbers live in PR bodies.
- **Structured logging for the GIN/generated-column deferrals** — any scoped-down decision (OQ-2/OQ-3) is recorded in the spike report and a code/`.planning` note, never a silent omission.

## Risks and rollback

| Risk | Mitigation | Rollback |
|---|---|---|
| **F1 rewrite is irreversible and the audit can't confirm it helps at scale.** | PR-0 spike (S2/S4) measures partition query perf + VACUUM/bloat *before* PR-1 is written; S6 can recommend descoping F1 if the numbers don't justify it. PR-1 uses a shadow-table-swap inside one migration txn (atomic). | If S6 says no-go, F1 is descoped and the sprint re-plans (F2/F3/F8 can proceed independently of partitioning). |
| **Rewrite migration hits `statement_timeout`/`lock_timeout` and aborts mid-flight on a large schema (RC-2).** | Migration opens with `SET LOCAL statement_timeout=0; lock_timeout='0'; idle_in_transaction_session_timeout=0`. S3 measures real wall-time so the operator knows the maintenance window. Single migration-txn = all-or-nothing. | Migration txn rolls back atomically; `variants_legacy` is only dropped at the end, so a failed swap leaves the original intact. |
| **Composite-FK + `chr` denormalisation breaks `ON DELETE CASCADE` on the six children (RC-1).** | P8 explicitly verifies cascade fires through `(variant_id, chr) REFERENCES variants(id, chr)`; backend-parity + a delete-path test on the partitioned schema. | Revert PR-1 migration design; the legacy single-FK schema is in git history. |
| **Exit criterion can't be met because annotating a WGS fixture is infeasible in the dev/CI budget (RC-6, OQ-1).** | PR-0 resolves OQ-1 with a fallback (synthetic annotations on a row fraction, documented). If even that fails, the exit gate is re-scoped to the representative-able subset + the annotated chr22 data scaled, recorded in S6. | Re-scope gate 8 in the spike report before PR-1; do not fabricate numbers. |
| **JSONB GIN ships and adds write-amplification with no reader (RC-5).** | OQ-2 default is to **defer** the GIN index; ship only if S2 shows it exercised. | Drop the `CREATE INDEX … USING GIN` line; JSONB type change stands alone. |
| **F8 renderer re-tasks the wrong component / `GeneBurdenView` confusion (RC-7).** | R3 + OQ-4 freeze placement at UI-spec time before PR-3; `GeneBurdenView` (association) is explicitly left untouched. | Renderer-only revert; backend materialisation (PR-2) stands. |
| **PG `getGeneBurden` `genome_build`-grouping fix (RC-8) changes results for multi-build cohorts.** | G2 mirrors SQLite exactly; G5 parity test includes a multi-build row, making the corrected behaviour the asserted one. | Parity test is the trip-wire; revert G4 read switch (live path in git history). |
| **Docker-init schema drift causes the rewrite migration to fail on a dev box (RC-10).** | P9 verifies `0012` on a Docker-init-bootstrapped schema; tests use the migration runner (the gated path). | Note in spike; align init scripts as a separate housekeeping task if needed. |
| **Web track regresses (shared read path / contract).** | `VARLENS_WEB=1 make ci` + web-gate parity on every PR; PR-2 changes only the PG read body (web inherits), PR-3 adds the web route in-PR. | Revert the web-layer change only; desktop unaffected. |
