Create src/main/services/api/ApiCache.ts:
- Constructor takes Database instance from better-sqlite3-multiple-ciphers
- Prepare statements in constructor (not on each call):
  - getStmt: SELECT response_data, created_at FROM api_cache WHERE cache_key = ? AND expires_at > ?
  - setStmt: INSERT INTO api_cache (cache_key, response_data, created_at, expires_at) VALUES (?, ?, ?, ?) ON CONFLICT(cache_key) DO UPDATE SET response_data = excluded.response_data, created_at = excluded.created_at, expires_at = excluded.expires_at
  - deleteByPrefixStmt: DELETE FROM api_cache WHERE cache_key LIKE ?
  - cleanupExpiredStmt: DELETE FROM api_cache WHERE expires_at <= ?
  - getCacheStatsStmt: SELECT SUM(CASE WHEN cache_key LIKE 'vep:%' THEN 1 ELSE 0 END) as vep_count, SUM(CASE WHEN cache_key LIKE 'hpo:%' THEN 1 ELSE 0 END) as hpo_count, SUM(LENGTH(response_data)) as total_bytes FROM api_cache
- Methods:
  - get(key: string): { data: string, createdAt: number } | null - check expiration, return null if expired
  - set(key: string, data: string, ttlDays: number): void - use Date.now() for timestamps
  - clearByPrefix(prefix: 'vep:' | 'hpo:'): number - returns deleted count
  - cleanupExpired(): number - returns deleted count
  - getCacheStats(): CacheSizeInfo - for settings page display
- Add TTL jitter: instead of exactly 30 days, use 27-33 days (random +/- 10%) to prevent thundering herd

Use existing api_cache table schema from migrations.ts. No schema changes needed.
  </action>
