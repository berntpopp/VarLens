Create src/main/services/api/VepApiClient.ts:

Import Bottleneck from 'bottleneck', zod schema from './schemas/vep-response', ApiCache from './ApiCache'.

Class VepApiClient:
- Constructor takes ApiCache instance (dependency injection for testability)
- Private limiter: Bottleneck configured for VEP rate limits:
  - reservoir: 55000 (55k requests per hour - Ensembl limit)
  - reservoirRefreshAmount: 55000
  - reservoirRefreshInterval: 60 * 60 * 1000 (hourly)
  - maxConcurrent: 1 (serialize requests for predictability)
  - minTime: 67 (67ms between requests = ~15 req/sec)
- Private abortController: AbortController | undefined (for request cancellation)
- Private baseUrl = 'https://rest.ensembl.org'

Retry handling via Bottleneck 'failed' event:
```typescript
this.limiter.on('failed', async (error, jobInfo) => {
  if (error.message.includes('429') && jobInfo.retryCount < 3) {
    // Exponential backoff: 1s, 2s, 4s
    const delay = Math.min(1000 * Math.pow(2, jobInfo.retryCount), 8000)
    // Add jitter: 50-100% of delay
    return Math.floor(delay * (0.5 + Math.random() * 0.5))
  }
  return null // Don't retry for other errors
})
```

Methods:
- async fetchVariantAnnotation(chr: string, pos: number, ref: string, alt: string): Promise<VepFetchResult>
  1. Generate cache key: `vep:${normalizeChromosome(chr)}:${pos}:${ref}:${alt}`
  2. Check cache first via this.cache.get(cacheKey)
  3. If cached and not expired, parse with VepResponseSchema, return { success: true, data, cacheInfo: { cached: true, cachedAt } }
  4. Cancel any pending request: this.cancelPendingRequest()
  5. Create new AbortController
  6. Schedule via limiter: `await this.limiter.schedule(() => this.makeVepRequest(...))`
  7. Validate response with VepResponseSchema.parse()
  8. Cache response with 30-day TTL (actual 27-33 with jitter)
  9. Return { success: true, data, cacheInfo: { cached: false, cachedAt: null } }
  10. Catch errors: AbortError -> re-throw (don't swallow), ZodError -> return { success: false, error: 'Invalid VEP response format' }, Other -> return { success: false, error: message }

- private async makeVepRequest(chr, pos, ref, alt, signal: AbortSignal): Promise<unknown>
  - Use GET endpoint for single variants (more reliable than POST per RESEARCH.md)
  - URL format: `${baseUrl}/vep/human/region/${chr}:${pos}:${pos}:1/${alt}?content-type=application/json`
  - Add query params for plugins: CADD=1, Downstream=1, SpliceAI=1, Conservation=1, Phenotypes=1 (verify availability)
  - Actually, VEP REST doesn't use query params for plugins - use vep/:species/region endpoint which returns available annotations
  - Correct URL: `${baseUrl}/vep/human/region/${chr}:${pos}:${pos}/${alt}?content-type=application/json`
  - Fetch with signal and Content-Type header
  - Check response.status === 429: throw Error('429:' + retryAfter)
  - Check !response.ok: throw Error(`VEP API error: ${status}`)
  - Return response.json()

- cancelPendingRequest(): void
  - If abortController exists, call abort() and set to undefined

- getCached(cacheKey: string): { data: VepResponse, createdAt: number } | null
  - For IPC handler to check cache when offline
  - Returns parsed VepResponse or null

- clearCache(): void
  - Call this.cache.clearByPrefix('vep:')

Helper function (can be in same file or utils):
- normalizeChromosome(chr: string): string
  - Remove 'chr' prefix if present: chr1 -> 1, chrX -> X
  - Uppercase MT handling: mt -> MT, chrM -> MT
  - For consistent cache keys across input variations
