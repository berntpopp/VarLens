  <name>Task 1: Create LogViewer drawer component</name>
  <files>src/renderer/src/components/LogViewer.vue</files>
  <action>
    Create `src/renderer/src/components/LogViewer.vue` as a single-file component using `<script setup lang="ts">`.

    **Props and model:**
    - `v-model:open` (boolean) -- controls drawer visibility, synced with parent via defineModel or modelValue/emit pattern

    **Template structure (top to bottom):**

    1. **Vuetify bottom drawer** (`v-navigation-drawer`):
       - `location="bottom"`, `temporary`, `:scrim="false"`
       - Height: `40vh`
       - `v-model` bound to open prop
       - Wrap contents in a flex column layout so toolbar stays fixed at top

    2. **Top toolbar** (`v-toolbar` with `density="compact"`):
       - Left: "Log Viewer" title text
       - Center-right area: Buffer usage display -- a `v-progress-linear` showing buffer fullness (e.g., "450/1000") with the current/max text as a label. If `stats.totalDropped > 0`, show a subtle "(X dropped)" text next to it.
       - Right: Action buttons (icon buttons, small):
         - Download icon (`mdi-download`) -- calls exportLogs
         - Delete/clear icon (`mdi-delete-outline`) -- calls clearLogs (show a simple confirm dialog or snackbar confirmation before clearing)
         - Close icon (`mdi-close`) -- sets open to false

    3. **Filter bar** (a `v-sheet` or `v-toolbar` below the main toolbar):
       - Search text field: `v-text-field` with `prepend-inner-icon="mdi-magnify"`, placeholder "Search logs...", `density="compact"`, `hide-details`, `variant="outlined"`, `clearable`
         - Bind to a local `searchInput` ref
         - Use `useDebounce` composable from `../composables/useDebounce` to debounce search value updates (~300ms). The debounced function updates a `debouncedSearch` ref that the computed filter uses.
       - Level filter chips: `v-chip-group` with `v-model="selectedLevels"` and `multiple`
         - One `v-chip` per level from LOG_LEVELS array (import from types/log)
         - Each chip: `filter` prop, `:value="level"`, `:color="LOG_LEVEL_COLORS[level]"` (import from types/log)
         - Label text: `{{ level }} ({{ bufferLevelCounts[level] }})` -- the count in parentheses serves as both stat display and filter control
         - All levels selected by default (initialize selectedLevels with all 5 levels)

    4. **Memory usage bar** (small inline display, below filter bar or in the toolbar):
       - Poll `performance.memory` every 5 seconds (with `setInterval` in `onMounted`, clear in `onBeforeUnmount`)
       - Display: "Memory: X.X MB / Y.Y MB" using `Intl.NumberFormat` or simple `toFixed(1)`
       - Cast `performance as any` to access `.memory` (non-standard but available in Electron/Chromium)
       - If `performance.memory` is unavailable, show "Memory: N/A"

    5. **Log entries list** (main scrollable area):
       - Use Vuetify `v-virtual-scroll` for performance with 1000+ entries
       - `:items="filteredLogs"` (computed, see below)
       - `item-height="64"` (approximate -- two-line card)
       - Each item renders as a card/div with:
         - Colored left border strip: 4px solid border-left using the level color (`border-left: 4px solid ${levelColorHex}` via inline style or dynamic class). Use Vuetify color utilities if possible (e.g., `border-s` with color class), otherwise inline style.
         - First line: Level badge (`v-chip` with `:color`, `size="x-small"`, `label` variant) + message text (truncated with ellipsis if too long). If `debouncedSearch` is non-empty, highlight matching text with `<mark>` tag (use a computed or inline function that wraps matches in `<mark class="bg-yellow">` using regex replace + `v-html`).
         - Second line: Timestamp (formatted with `Intl.DateTimeFormat` -- show time with seconds, e.g., "14:32:05.123") + source (if present, shown in grey italic)
       - **Auto-scroll behavior:**
         - Track a ref `isAutoScroll = ref(true)`
         - On scroll event of the virtual scroll container, detect if user is near bottom (scrollHeight - scrollTop - clientHeight < 50). If not near bottom, set `isAutoScroll = false`.
         - Watch `entries.length` -- if `isAutoScroll` is true, scroll to bottom on `nextTick`
         - Show a floating "Scroll to latest" `v-btn` (small FAB, bottom-right of the log area) when `isAutoScroll` is false. Clicking it scrolls to bottom and re-enables auto-scroll.
       - **Empty state:** When `filteredLogs` is empty, show a centered message: "No log entries" (if store is empty) or "No matching entries" (if filters are active but no results).

    **Script logic:**

    - Import: `useLogStore` from stores, `storeToRefs` from pinia, `useDebounce` from composables, `logService` from services, `LOG_LEVELS`, `LOG_LEVEL_COLORS` from types, `ref`, `computed`, `onMounted`, `onBeforeUnmount`, `nextTick`, `watch` from vue
    - Destructure store: `const logStore = useLogStore()`, `const { entries, stats, bufferUsage } = storeToRefs(logStore)` -- use storeToRefs for reactive state, NOT plain destructuring
    - `selectedLevels = ref([...LOG_LEVELS])` -- all selected by default
    - `searchInput = ref('')` and `debouncedSearch = ref('')` -- debounce wiring
    - `filteredLogs` computed: filter `entries.value` by selectedLevels AND debouncedSearch (case-insensitive includes on message and source)
    - `bufferLevelCounts` computed: count entries per level from current buffer (NOT cumulative stats -- recompute from entries array so counts match visible entries)
    - Memory polling ref + interval setup/teardown in onMounted/onBeforeUnmount

    **Important anti-patterns to AVOID:**
    - Do NOT destructure store without storeToRefs() -- breaks reactivity
    - Do NOT use `v-navigation-drawer` with `bottom` prop -- use `location="bottom"` (Vuetify 3)
    - Do NOT filter with watchers -- use computed properties
    - Do NOT create computed properties inside loops
    - Do NOT use reactive() for the entries array -- it's already a ref in the store

    4. **Keyboard shortcut (Ctrl+L):**
       - In `onMounted`, add a `keydown` event listener on `window`:
         ```typescript
         function handleKeydown(e: KeyboardEvent) {
           if (e.ctrlKey && e.key === 'l') {
             e.preventDefault() // prevent browser address bar focus
             logViewerOpen.value = !logViewerOpen.value
           }
         }
         window.addEventListener('keydown', handleKeydown)
         ```
       - In `onBeforeUnmount`, remove the event listener:
         ```typescript
         window.removeEventListener('keydown', handleKeydown)
         ```
       - Define `handleKeydown` at component scope (inside script setup, outside onMounted) so it can be referenced by both add and remove.
