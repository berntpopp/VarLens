  <name>Task 2: Create Pinia log store with circular buffer and LogService facade</name>

  <action>
    1. Create `src/renderer/src/stores/logStore.ts` as a Pinia SETUP store (not Options API):
       - Import types from `../types/log`
       - Define `CONFIG_KEY = 'varlens_log_config'` and `DEFAULT_CONFIG: LogConfig = { maxEntries: 1000, minLevel: 'debug' }`
       - `loadConfig()` function: reads CONFIG_KEY from localStorage, parses JSON, returns LogConfig (falls back to DEFAULT_CONFIG on parse error or missing)
       - `saveConfig(config: LogConfig)` function: serializes to JSON and writes to localStorage
       - Setup store `useLogStore` with:
         - `config = ref<LogConfig>(loadConfig())` -- reactive config initialized from localStorage
         - `maxEntries = ref(config.value.maxEntries)` -- derived from config
         - `entries = ref<LogEntry[]>([])` -- the circular buffer (use ref, NOT reactive, for arrays that get replaced)
         - `stats = ref<LogStatistics>({ totalReceived: 0, totalDropped: 0, debugCount: 0, infoCount: 0, warnCount: 0, errorCount: 0, criticalCount: 0 })`
         - Computed `bufferUsage`: returns `{ current: entries.value.length, max: maxEntries.value, percentage: (entries.value.length / maxEntries.value) * 100 }`
         - Action `addEntry(entry: Omit<LogEntry, 'id'>)`:
           - Assigns `id = stats.value.totalReceived`
           - If `entries.value.length >= maxEntries.value`, calls `entries.value.shift()` and increments `stats.value.totalDropped`
           - Pushes new entry to `entries.value`
           - Increments `stats.value.totalReceived`
           - Increments the appropriate per-level count in stats (use template literal key: `${entry.level}Count`)
         - Action `clear()`: sets `entries.value = []` (keep cumulative stats unchanged)
         - Action `setMaxEntries(max: number)`: updates `maxEntries.value`, trims oldest entries if buffer exceeds new max, updates totalDropped
         - Action `updateConfig(newConfig: Partial<LogConfig>)`: merges into config, calls saveConfig, updates maxEntries if changed
         - `watch(config, ...)` with `{ deep: true }` that calls `saveConfig(config.value)` whenever config changes
       - Return all refs, computed, and actions

    2. Create `src/renderer/src/services/LogService.ts`:
       - Import `useLogStore` from store, `sanitizeLogMessage` from sanitizers, `saveAs` from 'file-saver', types from types/log
       - IMPORTANT: Do NOT instantiate useLogStore() at module level. Pinia stores can only be used after Pinia is installed. Use a lazy getter pattern:
         ```typescript
         let _store: ReturnType<typeof useLogStore> | null = null
         function getStore() {
           if (!_store) _store = useLogStore()
           return _store
         }
         ```
       - Class `LogService` with:
         - Private method `log(level: LogLevel, message: string, source?: string)`: calls `sanitizeLogMessage(message)`, then `getStore().addEntry({ timestamp: Date.now(), level, message: sanitizedMessage, source })`
         - Public methods: `debug(msg, source?)`, `info(msg, source?)`, `warn(msg, source?)`, `error(msg, source?)`, `critical(msg, source?)` -- each calls `this.log(level, ...)`
         - Public method `exportLogs()`: creates JSON blob with `{ exportedAt: ISO string, appVersion: '0.2.0', stats: store.stats, entries: store.entries }`, saves using `saveAs(blob, 'varlens-logs-${Date.now()}.json')`
         - Public method `clearLogs()`: calls `getStore().clear()`
       - Export singleton: `export const logService = new LogService()` -- but ONLY after wrapping in a function or using the lazy pattern above so the store isn't accessed before Pinia init
       - Actually, since the class uses lazy getStore(), the singleton is safe at module level. The store is only accessed when a method is called, not at import time.
  </action>
