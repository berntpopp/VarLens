Add variant batch insert method to DatabaseService (DB-04):

**insertVariantsBatch(caseId: number, variants: Omit<Variant, 'id' | 'case_id'>[]): number**
- Verify case exists first (call getCase, let it throw NotFoundError if not)
- Prepare insert statement for variants table
- Use BATCH_SIZE constant = 5000
- Process variants in batches using this.transaction():
  - For each batch, iterate and run insert statement
- After all batches, update case variant_count with total
- Return total number of variants inserted

The Omit<Variant, 'id' | 'case_id'> type represents variant data without auto-generated fields:
- chr, pos, ref, alt, gene_symbol, consequence, gnomad_af, cadd, clinvar

Implementation pattern:
```typescript
const BATCH_SIZE = 5000

insertVariantsBatch(caseId: number, variants: Omit<Variant, 'id' | 'case_id'>[]): number {
  // Verify case exists (throws NotFoundError if not)
  this.getCase(caseId)

  const insert = this.stmt(`
    INSERT INTO variants (case_id, chr, pos, ref, alt, gene_symbol, consequence, gnomad_af, cadd, clinvar)
    VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
  `)

  const insertBatch = this.db.transaction((batch: Omit<Variant, 'id' | 'case_id'>[]) => {
    for (const v of batch) {
      insert.run(caseId, v.chr, v.pos, v.ref, v.alt, v.gene_symbol, v.consequence, v.gnomad_af, v.cadd, v.clinvar)
    }
  })

  for (let i = 0; i < variants.length; i += BATCH_SIZE) {
    const batch = variants.slice(i, i + BATCH_SIZE)
    insertBatch(batch)
  }

  this.updateCaseVariantCount(caseId, variants.length)
  return variants.length
}
```

Add paginated variant query with filters (DB-05, DB-06):

**getVariants(filter: VariantFilter, limit: number, cursor?: PaginationCursor): PaginatedResult<Variant>**

Build dynamic SQL query based on filter:

1. Start with base query:
```sql
SELECT * FROM variants WHERE case_id = ?
```

2. Add optional filters (all use AND):
- gene_symbol: `AND gene_symbol LIKE ?` (use `%${filter.gene_symbol}%` for partial match)
- consequence: `AND consequence = ?` (exact match)
- gnomad_af_max: `AND (gnomad_af IS NULL OR gnomad_af <= ?)` (include nulls)
- cadd_min: `AND (cadd IS NOT NULL AND cadd >= ?)` (exclude nulls)

3. Add cursor condition if cursor provided:
```sql
AND (pos > ? OR (pos = ? AND id > ?))
```

4. Add ORDER BY and LIMIT:
```sql
ORDER BY pos, id LIMIT ?
```
Fetch limit + 1 to detect hasMore.

5. For total_count, execute separate COUNT query with same filters (no cursor, no limit).

6. Build result:
- has_more = results.length > limit
- data = has_more ? results.slice(0, limit) : results
- next_cursor = has_more ? { id: last.id, sort_value: last.pos } : null

**Implementation notes:**
- Use parameter array that grows as filters are added
- Don't cache this statement (dynamic SQL)
- The total_count query should be cached if possible (separate statement per filter combo)

For search queries, add separate method:

**searchVariants(caseId: number, query: string, limit: number = 50): Variant[]**
- Use FTS5 MATCH with prefix search (append '*' to query)
- Join variants_fts with variants table
- Order by bm25(variants_fts) for relevance
- Return matched variants

```sql
SELECT v.* FROM variants v
JOIN variants_fts fts ON v.id = fts.rowid
WHERE v.case_id = ? AND variants_fts MATCH ?
ORDER BY bm25(variants_fts)
LIMIT ?
```
